# Security boundary

Experimental, unaudited, gasless test-network deployment. Do not use for custody, physical inventory, service-delivery certification or high-stakes allocation.

- Inputs are exact immutable published terms, not verified provider performance. A source author can lie about availability. Integrity does not establish authority, ownership, freshness or factual truth.
- Natural-language compatibility is independently derived for every pair, then exactly compared. Consensus can accept correlated model mistakes. Embedded instructions remain a prompt-injection risk even with explicit data boundaries.
- UNKNOWN enters only the hypothetical possible network. Source/schema failures produce HELD. Bad model output and disagreement do not publish a snapshot. No confidence tolerance can cross a decision threshold.
- Shared supply capacity cannot be spent twice inside one mathematical flow. Separate queries do NOT reserve or consume actual resources; they can analyze the same quantities again. No exclusive rights are created.
- Quantities and flow arithmetic are bounded integers. Lower/upper flow witnesses are checked for conservation and equality to cut capacity. The independent JS verifier enumerates all cuts.
- Source host, commit and path are restricted. Complete untruncated bytes are hashed and strict UTF-8 decoded. All schema keys and labels are checked; duplicate keys, bool quantities and caller labels fail validation.
- Immutable sender/contract/nonce keys prevent overwriting another snapshot. The input root includes the source and policy; report and output roots prevent context substitution. Sender quota is not Sybil protection.
- Root-bound assured_plan permits only TEXT_FEASIBLE and returns the lower flow. It is read-only, not authorization or certificate consumption.
- No owner, upgrades, transfers, external deterministic calls, signer private keys or credentials in repository. The demo uses an encrypted native keystore.
- Exact consensus can fail availability. Historical commit pinning intentionally does not prove currentness. No latest-truth update workflow exists.

Report issues privately using the repository owner's GitHub contact before publishing exploit details. Do not include keystore files, passwords, tokens or raw node/provider configuration in issues.
